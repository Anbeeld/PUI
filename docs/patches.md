# PUI patches

PUI owns the configuration and targeted patches that make its upstream components work as one reproducible application without a Pi fork. The [component reference](components.md) lists upstream packages and repository structure.

## Managed files and fields

PUI structurally merges the configuration JSON files below after making timestamped backups. The native recovery path also backs up `~/.pi/agent/npm/package.json` before asking npm to record its exact `node-pty` script approval:

- `~/.pi/agent/settings.json`: `defaultTools`, managed package entries, and explicitly retired package entries
- `~/.pi/web-search.json`: `searchRouting`, `fetchRouting`, and `workflow`
- `~/.config/mcp/mcp.json`: `mcpServers.playwright.command`, `args`, `lifecycle`, the six-tool `directTools` policy, and `settings.mcpFooterStatus`
- `~/.pi/agent/pi-goal.json`: `continuationLimits.automaticTurns` and `continuationLimits.noProgressTurns`
- `~/.config/rpiv-ask-user-question/config.json`: exact `guidance.description`, `guidance.promptSnippet`, and `guidance.promptGuidelines` values; an existing absolute `$XDG_CONFIG_HOME/rpiv-ask-user-question/config.json` takes precedence
- `~/.pi/agent/npm/package.json`: only the exact `node-pty` lifecycle approval when a native rebuild is required
- `~/.pi/agent/npm/node_modules/@99percentpeople/pi-background-tasks/index.min.js`: exact PUI-owned tool descriptions, prompt snippets, parameter descriptions, and six shared guidelines; the upstream bundle is retained as `index.min.js.pui-original` and ownership hashes as `index.min.js.pui-manifest.json`
- `~/.pi/agent/npm/node_modules/@gotgenes/pi-subagents/` sources listed by `stack.json.subagentsPromptPatch.files`: exact PUI-owned taxonomy, routing guidance, capability allowlists, unknown-type handling, per-instance running/queued limits, mapped-model, parent-reasoning, and completion-delivery policy; each upstream file is retained as `<file>.pui-original` and ownership hashes as `.pui-subagents-prompt-manifest.json`
- `~/.config/pui/subagents.json`: user-editable fuzzy model mappings plus `_pui.defaultMappings` reconciliation metadata; updates preserve user changes and deletions while adding newly shipped defaults
- Pi Web's resolved unbundled `node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session.js` and `@earendil-works/pi-agent-core/dist/agent-loop.js`: temporary exact Pi #8782 runtime backport; originals are retained beside the targets as `*.pui-8782-original` and ownership hashes as `.pui-pi-8782-backport.json`
- Exact Pi Web and standalone Pi compiled display/provider seams selected by `pui-reasoning-summary-patch.js` under the version and ownership policy in `reasoningSummaryPatch`: Responses reasoning-summary compatibility for any model using the managed Responses adapters, canonical Pi Web goal-command display, compaction-style typography for visible `Goal complete` bodies, and collapsed-by-default Pi Web subagent notifications; originals use `.pui-reasoning-original` and each runtime root records hashes in `.pui-reasoning-summary.json`
- `~/.pi/agent/extensions/pui-update/`: installed PUI identity and detached transaction worker

PUI owns the exact package pins for its added extensions, but it does not manage their account state, logs, or optional fields except where listed above. For `rpiv-ask-user-question`, install and update replace only the three managed guidance leaves while preserving fields such as `collapseKey` and unknown guidance siblings. Doctor requires an exact guidance match. Uninstall checks both the absolute XDG and legacy paths, backs up each matching file, and removes the exact PUI-managed guidance leaves only while they still match the complete owned shape; user-modified guidance is preserved.

For `@99percentpeople/pi-background-tasks`, PUI replaces the pinned 2.1.1 bundle's 27 overlapping prompt guidelines and verbose tool/schema descriptions with six compact shared guidelines and concise per-tool metadata. The version-anchored transform is sentinel-marked and idempotent, fails closed on metadata drift, is reapplied after each package reconciliation, and rebases its ownership artifacts onto the pristine bundle when `pi install` replaces the package for a new pinned version. Its hashed manifest records the pristine and patched bytes, allowing a later PUI-owned prompt revision to rebuild from the pristine backup without accepting user-modified output. Update transactions back up the bundle, original, and ownership manifest before mutation; staged target scripts retain this snapshot under one transaction-level guard until the enclosing worker reports success, so the introducing update remains reversible under an older installed worker. Doctor compares the installed bundle with the exact transform of its `index.min.js.pui-original`; uninstall restores that backup only while the installed output remains an exact PUI-owned match. The lifecycle entry points also verify that `node-pty` loads and approve/rebuild that dependency only when the bundled prebuild cannot load. For `@narumitw/pi-goal`, PUI preserves internal whitespace in new start objectives instead of rebuilding every parsed token with one ASCII space. The parser still recognizes the same subcommands and leading `--tokens` option, removes command-syntax quote delimiters, trims only the objective's outer whitespace, and leaves edit-command normalization unchanged. PUI also replaces the installed `formatStatus` bundle with a structured implementation that emits a readable `Goal: <status> · <reason> · <counter>` line (for example `Goal: paused · usage · 0/25`), with the counter omitted entirely when turns are unlimited. The completion path emits `Goal: complete · <elapsed>` before preserving upstream's eight-second status clear. PUI also defines an accepted `goal_complete.summary` as the complete user-facing response: it must include every deliverable required by the objective and concise verification where relevant rather than promise a later response. The patch removes upstream's 4,000-character schema cap, enforces Pi's 50 KB UTF-8 tool-output boundary at runtime, and never truncates accepted completion content. At `turn_end`, after Pi has persisted the accepted tool result, pi-goal first appends its hidden inactive contract and then emits the exact summary as an expanded durable `Goal complete` custom message with `triggerTurn: false`. Rejected completion calls are not promoted, no additional model request is made, and the original tool call remains under Process details. The replacement calls only cross-chunk imported helpers whose names the bundler preserves, never minified same-chunk locals. The patch is version-anchored to the pinned pi-goal release, marked with sentinel comments for idempotency, re-applied by install and update after every `pi install @narumitw/pi-goal`, and fails fast when its anchors drift so a version bump surfaces loudly instead of silently shipping an incomplete transform.

For `@gotgenes/pi-subagents`, PUI exposes exactly three built-in routes. `Explore` establishes local repository evidence with only `read`, `grep`, `find`, and `ls`; `Research` establishes external/current evidence with those local identification tools plus `web_search`, `source_check`, `fetch_content`, and `get_search_content`; `Worker` executes bounded decided work with upstream's seven built-ins and no extension tools. Each Pi extension instance permits up to 128 running background agents and retains a FIFO queue of up to 512 additional agents; a further spawn fails before creating an agent record and can be retried after capacity becomes available. User settings cannot raise the running ceiling above 128. Foreground agents retain upstream behavior and bypass this background limiter. The parent guidance includes a compact route-by-missing-work rule, foreground/background selection, mixed-evidence coordination, incomplete-result handling, and one prompt recipe per type. Foreground waits and runs sequentially; background returns an ID and runs concurrently when capacity is available or queues otherwise. Use background only when useful independent work can proceed before collection, never for overlapping writes or shared mutable state, and collect required results before dependent decisions, edits, or synthesis. Errors, aborts, stopped or max-turn outcomes, and partial output remain incomplete until retried with new direction, reassigned, or reported as a gap. The main agent owns user intent, overall architecture/planning, decomposition, synthesis, integration, final verification, and the response. Explicit unknown types fail before a Worker can be selected. Built-in `general-purpose` and `Plan` are removed without aliases, but user-defined profiles with those names remain selectable. The `thinking` argument is schema-limited to Pi's six supported levels.

PUI delivers a background completion queued during an active parent run at the next `turn_end`, after rechecking whether the result was already consumed. It sends the extension's existing notification as a steering message, so the next parent turn sees the result without creating a second notification; a send failure remains queued and `agent_settled` retries it as the fallback. Resume is ID-driven: the parent supplies the retained agent ID and a new prompt, while new-spawn type/model/reasoning/turn/background/context parameters are omitted and cannot block or alter the retained session. PUI also applies configurable default model and reasoning resolution. `~/.config/pui/subagents.json` contains parent-to-child mappings, initially the exact pair `openai-codex/gpt-5.6-sol` → `openai-codex/gpt-5.6-luna`. Custom mappings may still use fuzzy names. Both sides use the same exact-then-fuzzy resolver as the subagent tool's explicit `model` argument. If multiple keys resolve to the active parent, the invocation reports a configuration error; if the mapped child is unavailable, resolution falls back to the parent. An explicit invocation `model` wins over the mapping. An explicit invocation `thinking` also wins; when omitted, the child inherits the parent session's active reasoning level and Pi subsequently clamps it to the resolved child's capabilities. Agent-profile model and thinking defaults do not supersede these parented tool-invocation rules; none of the three PUI defaults hard-codes a model or reasoning level.

```json
{
  "schemaVersion": 1,
  "modelMappings": {
    "openai-codex/gpt-5.6-sol": "openai-codex/gpt-5.6-luna"
  },
  "_pui": {
    "defaultMappings": {
      "openai-codex/gpt-5.6-sol": "openai-codex/gpt-5.6-luna"
    }
  }
}
```

Users edit `modelMappings`; `_pui.defaultMappings` records the last defaults PUI offered so later updates can distinguish an untouched mapping from one the user changed or removed. Reconciliation compares mapping keys case-insensitively, preserves user key spelling, and rejects case-duplicate keys before they can resolve twice. A missing file means no mappings and falls back to the parent model; malformed configuration fails closed.

Install and update reconcile shipped defaults through the config's `_pui.defaultMappings` metadata. A newly shipped key is added, an untouched shipped value can be updated or retired, and a mapping the user changed or deleted is preserved. Unrelated fields also remain intact. PUI owns the installed default source, while supported user overrides and additions live in project `.pi/agents/*.md` or global `~/.pi/agent/agents/*.md`; lifecycle operations never mutate those files. Registry overlay is case-insensitive, so project profiles override global profiles and user profiles override PUI defaults regardless of filename case. An overridden built-in name is treated as custom: its listed user description and capabilities replace the PUI default route assumptions. New or changed profiles are reload-resolved immediately when named exactly; the parent-facing displayed profile catalog refreshes on the next session. Custom profiles are selected only when the user names one or its listed description is the best match, and their prompts state task, scope, constraints, listed capabilities, success criteria, and output without assuming unlisted tools.

The version-anchored source transform is sentinel-marked and idempotent, fails closed on version, metadata, schema, or unknown ownership-revision drift, and is reapplied after package reconciliation. Exact prior revisions migrate from pristine backups. Artifact and snapshot writes use same-directory temporary files plus atomic rename. A durable package-local journal restores an interrupted patch or restore before the next lifecycle mutation, while update transactions retain the outer snapshot until validation succeeds; an already-current patch performs no source/manifest rewrite. Doctor validates both the user mapping schema and the installed transform. Uninstall supports every exact known owned revision, restores backups only when the pinned package identity and installed files still match that PUI-owned shape, and leaves user profiles and mapping config in place.

PUI's reasoning-summary patch applies to any model using the managed OpenAI, Azure OpenAI, or Codex Responses adapters; it does not inspect or restrict the provider name. During streaming, the provider parser keeps validated summary deltas in a separate transient buffer, so raw reasoning in the normal thinking buffer cannot become display text. The transient `puiReasoningSummaryText` marker is accepted only by an explicitly live streaming projection. Final, persisted, deferred, and exported messages are projected only from signatures containing a non-empty array made entirely of string `summary_text` entries. The render-only projection leaves original thinking blocks, encrypted replay content, signatures, grouping, persistence, and token accounting intact. It applies to Pi Web's transcript, reconnect event stream, previews, deferred history endpoint, context loading, and HTML export, plus standalone Pi's TUI and HTML export. The same Pi Web projection strictly recognizes pi-goal's owned initial and explicit-resume prompt shapes and displays canonical `/goal …` or `/goal resume` text without changing stored prompts or model context; continuations and other generated goal messages are unchanged. When the slash-command request finishes after starting an extension-driven goal turn, Pi Web defers that request's transcript reload while the extension run remains active, preserving the optimistic command until the live or end-of-turn reconciliation can replace it with persisted projected content. A summary whose complete Markdown content is bold has its enclosing bold markers converted to italic markers, including multiline and multi-paragraph summaries; mixed emphasis remains unchanged. Non-Responses APIs retain upstream behavior.

In Pi Web, `subagent-notification` custom-message cards retain their existing color and header but start as a single tool-like row with the timestamp immediately left of a chevron. As with tool rows, clicking anywhere on the header—or focusing it and pressing Enter or Space—toggles expansion. Expanding restores the existing content, Copy action, and Details action; collapsing hides those rows again. When an extension starts a run while Pi Web is reconnecting, the client schedules one persisted-transcript reload and performs it at the first assistant snapshot, after the custom prompt has been persisted, so that prompt is not lost in the connection gap or by a reconciliation race. The slash command's own `prompt_done` event does not start a competing stale transcript reload while that extension run is active. A replayed user-message start cancels the pending reload, narrowing reconciliation away from ordinary UI-started runs. The visible `Goal complete` custom-message body alone reuses Pi Web's existing compaction Markdown class, giving it the 1.5 line height and paragraph, heading, list, quote, table, and code spacing intended for long summary content; its generic custom-message card and controls remain unchanged. Other custom-message types keep their upstream initial expansion behavior and presentation.

The exact-version transform patches only runtime-loaded compiled artifacts. It runs after branding because both transforms touch Pi Web page bundles, then versions browser references from the final display-patched client bytes so stale browser code cannot remain cached; uninstall removes it before restoring branding. Hashed manifests and distinct `.pui-reasoning-original` sidecars support verification, npm reconciliation, migration from an older verified PUI revision, checked removal, and cross-runtime rollback. Snapshot restoration preflights live artifact bytes, replaces files atomically, and rewinds already-restored artifacts if a later restore operation fails; invalid snapshot evidence and restore I/O failures are reported separately. Staged updates retain a snapshot until the outer transaction reports success, including when the installed worker predates this patch.

PUI's Pi #8782 backport is a temporary exact-version compatibility shim for the runtime used by Pi Web. Pi 0.84.3 can let a completed tool result cross the normal threshold before the next provider request; PUI's helper backports only upstream PR #8782's agent-loop scheduling and AgentSession between-turn compaction into the resolved unbundled Pi Web dependency tree. It does not patch the standalone bundled `pi` CLI (`dist/bundle/cli.js`), change compaction thresholds, add a new dependency, build Pi, or include the upstream TUI progress-indicator hunk. The standalone CLI therefore remains stock 0.84.3 while Pi Web uses 0.84.3 plus this backport. The helper resolves private packages from Pi Web rather than guessing a global path, requires the exact `@agegr/pi-web` 0.8.11 / Pi 0.84.3 composition, transforms both files in memory, syntax-checks them, records a hashed ownership manifest, and restores both originals only when the complete owned shape remains intact. Install and update apply it after runtime parity and before restart; doctor fails when it is absent or drifted; uninstall removes it from the default path; the helper is retired when PUI pins the first released Pi version containing #8782.

PUI's MCP policy is proxy-first: servers stay available through the `mcp` tool, and only frequently used operations are promoted through a server's `directTools` list. PUI does not set `settings.disableProxyTool`, overwrite global adapter settings, or apply its Playwright policy to unrelated MCP servers. Doctor compares `mcpFooterStatus` with `stack.json` and reports a missing or drifted value as `FAIL`.

It may also write one per-user autostart file:

- Windows: `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\pui-piweb.vbs`
- macOS: `~/Library/LaunchAgents/com.pui.piweb.plist`
- Linux: `~/.config/systemd/user/pui-piweb.service`

Uninstall regenerates the platform's complete canonical PUI content and removes the entry only on an exact match. A same-named file that was edited, moved to a different launcher path, or is otherwise unrecognized is preserved with a warning.

The branding helper patches only Pi Web's top-level title, description, sidebar brand, manifest, favicon, Apple touch icon, and PWA icon metadata. Component-name occurrences such as release text remain “Pi Web.” It also shrinks the footer widget-trigger cell from its fixed 70% shelf basis to content width (keeping the 70% cap and horizontal scroll) so a single extension widget does not leave a large empty gap next to the status text, and drops the now-adjacent duplicate right border on the last trigger. Original build files are stored as `*.pui-original`, the service-worker cache name receives a PUI suffix, update reapplies the override, and uninstall restores the originals.

The update integration is pinned to the exact Pi Web version in `stack.json`. It replaces the existing `/api/app-update` implementation through a narrow expected-pattern check and injects one public client script into the prerendered app document. Apply and removal snapshot every owned artifact, change the ownership manifest last, and compensate back to the pre-operation bytes if an intermediate write or deletion fails. Its separate ownership manifest and backups allow uninstall to restore it only while the complete installed shape still matches PUI.

The injected client renders the update notification card and an always-visible Restart PUI control (reusing the card styling, positioned below the notification). Restart sends `PUT /api/app-update`; the bridge rejects the request with HTTP 409 while an update or restart is already in progress, marks the status as restarting, then spawns a detached restarter that stops the managed Pi Web processes and relaunches Pi Web through the same launcher as autostart (the hidden Startup-folder VBS on Windows, `launchctl kickstart -k` on macOS, `systemctl --user restart` on Linux, falling back to a detached `pi-web --no-open` when no managed autostart exists). The restarter writes progress to the update status file and only reports success after Pi Web answers HTTP again. The client shows the restart phases on the card: on success the page reloads (returning an active Restart control); on failure the card reports the error and the button is re-enabled. Before any bridge action loads `updater.js`, the bridge verifies the manifest's exact four-file extension shape and every recorded SHA-256. Detached update and restart workers carry a mandatory identity-check marker and repeat the same adjacent-manifest verification before executing; missing, extra, or drifted installed files fail closed. The restarter runs from the installed `updater.js` and never goes through the update transaction's idle gate.

Autostart suppresses Pi Web's npm updater because PUI owns the complete pinned composition. The PUI card checks the latest stable GitHub release once per app launch. After explicit approval, a detached worker stages tagged snapshots in OS temporary storage, waits for managed work to become idle, applies the target, and rolls back to the previous manifest-defined composition on failure. Transaction status is temporary and survives only long enough for the app to report the result.

## Files PUI does not manage

- `~/.pi/agent/sessions/`: user session data
- `~/.pi/agent/models.json`: model and provider configuration
- `~/.pi/agent/auth/`: credentials
- Project `AGENTS.md`, `CLAUDE.md`, and `.pi/settings.json` files outside this repository
- Host-specific MCP configuration for other applications
